## 별도 상태가 있으나 초기에는 재사용 가능한 3종

| 상태 이름 | 조건 | 초기 재사용 제안 |
|---|---|---|
| Alert | 경계 영역 진입, 접근 관찰 | Idle을 재사용 가능. 전용 위협 동작은 나중에 추가 |
| Recovery | 정상 돌진 종료·절벽 중단·피격 후 대기 | Idle 또는 짧은 숨 고르기. 현재 최소0.8초이며 남은 쿨타임도 기다림 |
| Stagger | 슈퍼아머가 없는 상태에서 약한 피격 | 전용 움찔이 있으면 좋지만 초기에는 중립 자세로 대체 가능 |

따라서 기본 상태는9개지만, **처음부터9개를 별도로 그릴 필요는 없다.** 경고는 현재 Debug.Log로 확인하고, 사용자 VFX 슬롯은 기본 None이다.

## 강한 피격을 시각적으로 구분할 때 추가할 3종

| 상태 이름 | 기존 공통 피격 단계 |
|---|---|
| KnockdownLaunch | 강한 타격으로 날아가는 동안 |
| KnockdownDown | 착지 후 쓰러져 있는 동안 |
| GetUp | 자동으로 회복하는 동안 |

이3개도 Controller와 표시 컴포넌트에 자리를 준비한다. 현재 기본 대검 공격은 Stagger이므로 우선 제작 대상은 아니다. 벽 충돌의 Stun과 강한 피격의 KnockdownDown은 다른 상태다. GetUp은 피격 복구이며, 경계할 때 일어서는 동작을 추가한 것이 아니다.

## 연결 구조

- `BoarBrain`: 행동 상태·방향·상태 진행률만 제공한다.
- `BoarMotor`: Rigidbody2D 이동과 지형 감지를 담당한다.
- `BoarAttack`: 돌진 중 시간/이동 구간의 타격만 담당한다.
- `BoarAnimator`: 위 상태와 CombatHealth/CombatReaction을 읽어 몸 표시를 선택한다. 공격·속도·피해를 발생시키지 않는다.
- 표시 우선순위: 사망 → 실제 피격 반응 → Alert/Windup/Charge/Recovery/Stun → 실제 이동에 따른 Walk/Idle.
- Windup/Charge/Recovery/Stun은 전투 상태 진행률을 직접 샘플링한다. 다른 상태는 일반 재생이며 Death 클립은 추후 import할 때 비반복으로 설정한다.
- 각 상태 경로와 `invertSpriteFacing`은 BoarAnimator Inspector에서 바꿀 수 있다. 원본 방향이 확인되기 전 특정 방향을 영구 확정하지 않는다.

## 아트가 준비됐을 때

1. 위 원본 폴더에서 해당 프레임을 가져온다. 원본 픽셀과 기존 GUID를 보존한다.
2. Point/32PPU/무압축/mipmap 없음으로 설정하고, 클립 전체에 일정한 발·몸 기준점을 맞춘다. 매 프레임 자동 중앙 정렬로 보행 흔들림을 지우지 않는다.
3. 기존 Boar.controller 상태의 Motion에 클립을 연결한다. AI나 피해 코드를 수정할 필요는 없다.
4. `CharacterVisual`은 이미 로컬Y=-0.45의 발 기준, scale1이다. 이 Renderer를 켜고 임시 `Square` Renderer를 끈다. Rigidbody/Collider는 루트에 유지한다.
5. 좌우 방향·Idle/Walk 전환·벽 기절·피격·Death 마지막 프레임을 실제 플레이와 카메라 캡처로 검토한다. 캔버스 크기나 몸 형태가 바뀌면 원본의 투명 여백과 실제 몸 크기를 구분해 맞춘다.

현재 사용자의 애니메이션 제작을 기다리는 구조이며, 이번 구현에서 원화·VFX·가짜 동작 클립은 만들지 않는다.
