## 최신 연결 상태 — 2026-11-03

사용자 제공 Idle/Walk/Attack/Death 각 16프레임을 반입하고 BadgerAnimator·클립·컨트롤러·프리팹 연결을 저장했다. 추가 접근 engageRange=2.5u 조건도 연결했다. 오른쪽 기본, 왼쪽 flipX, Point/32 PPU/무압축/Mipmap off. Stagger 미제공으로 피격 중 Idle 첫 프레임 유지. 기존 일어서기 제외 결정을 유지한다. 초기 Unity 시작 실패 후 재시도에서 실제 Editor API 생성과 Editor74/Play12 총86개 검사가 통과했다. 임시 검증 파일 정리 후 영구 Runtime30/Editor8 분리 컴파일도 통과했다. 정밀 타격 시각·원화/판정 크기와 사용자 조작감은 별도 검토가 남아 있다. 세부 파일/동작/직접 확인은 Docs/Reports/2026-11-03-badger-animation-link.md를 따른다.

아래 1~7절은 직전 **설계 시점 기록**이다. 그 안의 “아직 미구현/문서만 수정”은 그 당시 상태이며 최신 저장 상태는 이 구역과 보고서가 우선한다.

## 1. 최신 결정과 범위

2026-11-03 사용자 후속 결정: 제작 부담을 줄이기 위해 일어서기를 제거한다. 그에 따른 다시 내려가기·직립 전용 보행·자세 전환 대기와 전용 상태도 설계에서 제외한다. 이번 문서가 직전 일어서기 제안을 대체한다.

영역 침입 → 제자리 경계 → 플레이어가 더 접근하면 추적·공격한다는 거리 조건은 유지한다. 평상시와 경계·추적 사이에 자세 전환을 요구하지 않는다. 구체적 외형이나 보행 자세를 새로 확정하지 않는다.

이번에는 설계와 협업 기록만 수정한다. 기존 BadgerBrain에는 일어서기 상태나 클립이 구현되지 않았으므로 삭제할 런타임 코드는 없다. 정사각형 프리팹·기존 수치·스프라이트·씬을 바꾸지 않는다.

## 2. 행동 흐름

1. Idle: 대기.
2. 바깥 detectionRange 진입 → Alert: 제자리에서 경계. 진입 Debug.Log 1회, 사용자 경고 prefab이 있으면 표시하고 None이면 표시 없음.
3. 같은 거리에 머물면 경계 유지. 더 작은 engageRange 안으로 들어오면 Chase.
4. Chase: 이동, 공격 거리에서는 Windup → Active → Recovery. 회복 후 다음 공격 또는 추적.
5. 경계 중 이탈하면 Idle, 추적 중 이탈/한계 초과/도달 불가는 Return → 홈 도착 즉시 Idle.

일어서기/내려가기 클립 완료를 기다리는 단계는 없다. 피격·사망이 일반 행동보다 우선한다. 바깥 감지 범위 > 추적 시작 범위 > 공격 범위이며, 추적 시작/해제 경계의 반복을 막기 위한 거리 차이를 검토한다. 수치는 추후 Inspector 튜닝 대상이다.

현재 코드는 alertTime 후 자동 Chase이므로 위 추가 접근 조건은 아직 구현되지 않았다. 이번 문서 변경만으로 AI가 새 거리 정책을 따른다고 기록하지 않는다. 기존 경고 시간은 최소 경고 시간으로 사용할 수 있으나 자세 전환 시간으로 사용하지 않는다.

## 3. 필요한 기본 애니메이션: 5개

| 클립 | 동작 | 반복 | 사용 상태 |
| --- | --- | --- | --- |
| Idle | 기본 대기 | 반복 | Idle와 Alert가 공유 |
| Walk | 보행 | 반복 | 실제로 이동하는 Chase/Return |
| Attack | 준비 → 타격 → 회수 | 1회 | Windup/Active/Recovery |
| Stagger | 짧게 맞고 움찔한 뒤 복귀 | 1회 | 일반 피격 |
| Death | 쓰러지고 마지막 자세 유지 | 1회 | 사망 |

경계 전용 대기 클립은 필수 제작 목록에 넣지 않는다. 경고는 요청한 Console 로그와 사용자 VFX 슬롯으로 구별한다. 제작 순서는 Idle → Walk → Attack → Stagger → Death를 추천한다. 프레임 수·FPS·구체적 공격 자세는 확정하지 않는다.

강한 피격까지 완전히 표현하려면 KnockdownLaunch / KnockdownDown / GetUp 3개를 추가해 총 8개가 된다. 일반 경계에서 일어서는 동작은 제거하지만, Knockdown에서 넘어진 뒤 회복하는 GetUp은 다른 기능이다. 공통 CombatReaction의 Launch → Down → GetUp 동작을 삭제하지 않는다. 현재 오소리 일반 공격은 Stagger이며, 이 추가 클립은 오소리가 강한 피격을 받는 경우를 위한 목록이다.

## 4. 클래스·Animator 구조

| 대상 | 책임 |
| --- | --- |
| BadgerBrain | 영역·추가 접근·추적·공격·복귀 결정. 자세 전환 상태/시간은 추가하지 않음. |
| BadgerData | 감지/추적 시작/공격 거리와 기존 전투 시간. |
| BadgerAnimator(향후 추가 제안) | Brain/Reaction/사망/실제 속도를 읽어 위 클립을 선택하고 좌우 표시 반전. |
| BadgerMotor | 실제 물리 이동과 지형 검사. |
| BadgerAttack | 데이터의 Active 시간에만 피해 판정. |
| CombatReaction / CombatHealth | 피격 단계·자동 기상·사망 상태 관리. |

Base Layer 하나로 시작한다. 표시 우선순위는 사망 > Knockdown 단계 > Stagger > 공격 > 실제 보행 > Idle이다. AI가 Chase여도 실제 속도가 0이면 Idle 표시가 적절하다.

루프는 상태 진입 시 재생하고 같은 상태를 매 프레임 처음부터 시작하지 않는다. Attack은 전투 진행률과 동기화한다. 피격/사망은 Exit Time을 기다리지 않고 전환한다. 애니메이션이 Rigidbody·루트 위치·콜라이더를 직접 움직이지 않는다. Animation Event가 피해 허용/접근/착지/기상 완료 같은 게임 규칙을 결정하지 않는다.

현재 Attack 임시 시간은 준비 0.35s / 타격 0.12s / 회수 0.65s, 총 1.12s다. 한 클립에서 준비 0~0.3125, 타격 0.3125~약 0.4196, 이후 회수로 맞추는 안이다. 실제 아트를 연결할 때 타격 그림과 Active를 함께 검토한다. 이번에 클립을 생성하거나 시간을 바꾸지 않는다.

## 5. 제작·연결 원칙

현재 캐릭터 크기 기준, 32 PPU, Point·무압축·Mip Map 끄기를 따른다. 모든 프레임에 같은 캔버스와 일관된 발 기준 피벗을 사용한다. 정확한 오소리 아트 크기·외형·캔버스는 이번에 임의 확정하지 않는다. 다른 대화의 생성 이미지도 자동으로 반입하지 않는다.

현재 정사각형 물리 크기는 0.7×0.7u다. 실제 아트를 연결할 때 몸체와 공격 판정이 맞는지 별도 검토하며 이번에는 바꾸지 않는다. 경고 VFX는 사용자 prefab만 사용하고 임의 디자인·HUD·Gizmo를 만들지 않는다. 향후 임시 Gizmo를 쓰더라도 기능 완료 전에 전부 제거한다.

## 6. 향후 구현·검증

예상 코드 변경은 BadgerBrain/BadgerData의 추가 접근 조건과 BadgerAnimator 연결이다. 일어서기·내려가기·직립 전용 클립/상태/진행률은 구현 대상에서 제외한다. 향후 필요한 일반 공격·피격 진행률과 이동 속도만 표시 담당자에 전달한다.

검증: 바깥 영역 진입 시 제자리 경계 → 머물러도 추적하지 않음 → 더 접근하면 추적/공격 → 이탈/복귀 후 Idle. 급접근·거리 경계 왕복·피격/사망 우선순위·벽에 막힌 보행·사용자 경고 prefab None/연결·완료 후 Gizmo 0개도 확인한다. 새 거리 조건/Animator는 아직 미구현이다. 과거 22개 전투 검사를 새 정책의 실행 증거로 사용하지 않는다.
