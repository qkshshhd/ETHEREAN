## 3. 실제 구현 흐름

1. Space를 누르면 Reader의 performed 이벤트가 점프 요청을 보관한다. IsJumpHeld는 복제된 Jump 액션의 IsPressed를 읽는다.
2. PlayerMovement.FixedUpdate가 기존 바닥/코요테 권한을 검사하고 점프를 실행한다. Y속도 12를 설정하며 이번 점프의 절단 권한을 연다.
3. Space를 놓으면 canceled 이벤트가 해제 요청을 보관한다. ConsumeJumpRelease가 다음 물리 업데이트에서 한 번 소비한다.
4. 상승 중 해제 요청이 있거나 더 이상 키를 유지하지 않으면 ApplyJumpCut이 현재 Y속도 × jumpCutMultiplier를 반환하고 절단 권한을 닫는다. 물리 틱 전에 누르고 놓은 짧은 입력도 시작 속도를 줄인다.
5. 공중에서는 상승 중 24u/s², 낙하 중 48u/s²의 가속도를 적용한다. 최대 낙하 속도는 기존 20u/s다. X와 Y는 PlayerMovement가 한 번에 적용한다.
6. 착지하면 기존 점프 권한을 복구한다. 키를 계속 누른 채 착지해도 자동 반복하지 않는다.

## 4. 설계 근거·트레이드오프

입력 Reader는 버튼 정보만 전달하고, 이동 정책과 물리 속도는 PlayerMovement에서 계산한다. 기존 작은 추상 입력 계약을 확장하며 새로운 인터페이스나 상태 머신을 추가하지 않는다. GroundSensor는 계속 바닥만 검사한다.

순간 상승 속도 절단은 코드와 조정값이 작고, 최대 점프 높이를 유지하기 쉽다. 한 번만 적용하므로 키를 놓은 매 틱마다 속도가 절반으로 줄어드는 지수 감쇠를 피한다. 배율 0.5는 남은 속도의 절반이며 최종 점프 높이의 절반을 의미하지 않는다. 재누름은 줄인 속도를 복원하지 않는다.

유지 상태만 검사하면 같은 물리 틱 사이의 해제·재누름을 놓칠 수 있어 해제 이벤트도 한 번 보관한다. 이 보관은 다음 물리 틱까지의 입력 전달이며 착지 입력을 예약하는 점프 버퍼가 아니다.

낙하 중력은 상승 중력과 독립적이므로 상승 높이를 바꾸지 않고 착지를 빠르게 한다. 최대 낙하 속도에 도달한 뒤에는 기존 20u/s 제한을 유지한다. 수치가 클수록 해제 시 변화나 낙하가 급하게 느껴질 수 있어 사용자 조작감 검토가 필요하다.

## 6. 직접 확인 절차

1. `Assets/_Project/Scenes/Tests/PlayerMovementTest.unity`를 열고 Game 뷰를 16:9로 설정한다.
2. Play를 누른 후 Game 뷰를 클릭한다. 중앙 평지에서 Space를 짧게 누른 뒤 약 0.2초 유지, 충분히 오래 유지하는 동작을 비교한다. 길게 유지할수록 최고 높이가 커져야 한다.
3. 상승 중 Space를 놓았다 다시 눌러도 추가 점프하거나 높이가 복원되지 않아야 한다. 정점 이후 놓아도 낙하가 느려지지 않아야 한다.
4. 계속 누른 채 착지해도 자동으로 점프하지 않고, 놓았다 새로 누르면 다시 점프해야 한다.
5. 왼쪽 초록 발판에서 걸어 나온 직후 Space로 코요테 점프를 한 뒤 일찍 놓아 높이 조절이 되는지 확인한다. 오른쪽 갈색 천장 아래에서는 상승이 막혀야 한다.
6. Player Movement Inspector에서 Jump Cut Multiplier를 조정한다. 0은 키를 놓을 때 상승 중단, 1은 고정 높이와 같다. Fall Gravity를 36과 48로 비교한다. 유지할 값은 Play를 종료하고 프리팹에서 설정한다.

## 7. 임시값·제한

| 항목 | 값 |
| --- | --- |
| jumpCutMultiplier | 0.5 (신규) |
| fallGravity | 48u/s² (이전 36) |
| riseGravity / jumpSpeed | 24u/s² / 12u/s (유지) |
| maxFallSpeed / coyoteTime | 20u/s / 0.1초 (유지) |

현재 이동 속도는 여전히 임시 Inspector 값이다. 캐릭터 스탯 시스템과 점프 버퍼는 구현하지 않는다. 입력·충돌 결과는 FixedUpdate 간격으로 반영되며 최종 수치는 조작감 검토 후 조정한다.
