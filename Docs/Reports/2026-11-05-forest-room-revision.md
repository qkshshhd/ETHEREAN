# 첫 숲 B–C 방 경계 수정

[수정된 숲 씬](../../Assets/_Project/Scenes/ForestWhitebox.unity) · [B–C 단면도](2026-11-05-forest-room-revision-map.png)

사용자 피드백에 따라 B 갈림길에서 하층 C로 들어가는 구간을 **갈림길 → 뿌리 하강 연결방 → 오소리 방**으로 나눴다. 첫 오소리 방의 바닥은 y=-4u에서 **y=-8u**로 낮췄다. B와 C 사이에는 약 **15.25u** 길이의 계단식 통로, 폭 3u의 중간 착지 공간, 깊이에 따라 낮아지는 암반 천장이 있다. C에서 D 쪽은 0.8u 상승 단차 다섯 개로 기존 y=-4u 진입 높이에 다시 연결된다.

물리적으로는 통로를 걸어서 왕복하는 기존 방식이다. 문을 넘는 순간 카메라만 다음 방으로 잘라 보여주므로, 위치 이동이나 씬 전환 없이 공간 경계를 확인할 수 있다. 방 범위는 Inspector의 **Rooms → Entry Bounds / View Bounds**에서 조정한다. 아직 방을 정의하지 않은 구간에서는 기존 월드 카메라가 작동한다. 화면 페이드와 방 단위 로딩은 이번 작업에 포함하지 않았다.

높이 차이는 통로 전체에 분배했다. 필수 상승 단차는 주로 **0.8u**로 잡았고, C↔E 입구의 틈 **1.25u**는 그대로 유지했다. 기존 플레이어 이동 수치와 저장 슬롯, D~I의 진행 조건은 유지했다. 기존 전체 단면도는 수정 전 배치다.

## 직접 확인

1. `ForestWhitebox`를 Play하고 A에서 오른쪽으로 이동한다.
2. B에서 오른쪽 끝까지 걸으면 시야가 좁은 하강방으로 넘어간다. B 화면에서 아래층 오소리가 보이지 않아야 한다.
3. 중간 착지 공간을 지나 끝까지 내려가면 C의 별도 화면이 열린다. C 초입의 작은 틈은 Space로 건너고, 오른쪽 상승턱들을 지나면 기존 D 방향으로 이어진다.
4. 첫 검토 기준은 **B에서 C가 새어 보이지 않는지**, **하강 거리감이 충분한지**, **경계에서 화면 전환이 지나치게 급하지 않은지**다. 다른 층에도 이 방 구성 기준을 확장하는 작업은 아직 하지 않았다.

## 검증 상태

- C# Runtime 및 Editor 독립 컴파일 통과.
- `node Logs/CheckForestRoomRevision.cjs`: 씬 내부 참조, 연결방 계단 연속성, C의 1.25u 틈, C→D 연결, C↔E 발판 12개 및 진행 조건 보존 확인. 기존 프리팹 인스턴스의 위치 변경은 C 오소리 둘과 C 아이템으로 한정됐다.
- Unity Play 재검증 대기. 임시 `ForestRoomRevisionValidation.cs`와 `ForestRoomRevisionDriver.cs`는 에디터가 새로고침하면 복제 씬에서 실제 입력으로 세 방을 통과하는 검사에 사용한다. 이 단계의 Unity 통과를 아직 주장하지 않는다.
