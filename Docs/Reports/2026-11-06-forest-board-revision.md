# 첫 번째 숲: A~I 화이트박스 개편

사용자가 준 두 보드의 공통 진행 순서 **A → B → C → D → E → F → G → H → B → I**를 실제 숲 씬에 적용했다. 그림의 치수는 초안이므로 기존 0.5u 그리드, 기본 점프의 이전 실측 1.352u, 벽차기 능력 해금 순서에 맞춰 배치했다. [좌표에서 그린 전체 배치](2026-11-06-forest-board-layout.png)는 Unity 캡처가 아닌 저장 지형 단면도다.

| 구간 | 씬에서 바뀐 점 |
| --- | --- |
| A 숲 입구 | 시작 벤치를 왼쪽의 낮은 지형으로 옮기고, 안전한 오르막과 낮은 턱을 지나 B에 연결했다. 전투는 없다. |
| B 산길 갈림길 / BC 뿌리 하강로 | B의 편집 가능한 바닥, 경사 타일, 선택 샛길은 유지했다. 기존 I 암벽 사이에 주황색 뿌리 잠금을 놓았다. 하강로에는 중간 경사와 높이가 다른 천장을 두고 C에 연결했다. |
| C 하층 숲 | x66~104u로 넓혔다. 입구의 낮은 관찰 언덕, 오소리 한 마리와 회복 아이템, D로 올라가는 계단을 배치했다. C↔E 입구는 닫혀 있을 때 본길의 바닥이 되고, 개방 후에는 오르내릴 수 있는 1.5u 폭의 통로가 된다. |
| D 뒤집힌 뿌리굴 | 높은 관찰 지점에서 17u 폭의 멧돼지 전투장으로 내려간다. 왼쪽의 단방향 발판으로 도중에 물러날 수 있다. 오른쪽 뿌리는 멧돼지를 이기고 상호작용하면 열리며, 뒤쪽의 하강 발판이 E 바닥으로 이어진다. |
| E 숲속 쉼터 | 전투가 없는 하층에 벤치를 두고, 왼쪽에 C↔E 지름길을 여는 지점을 둔다. D에서 벤치까지 돌아오는 길에는 낮은 언덕을 배치했다. 지름길은 12개의 단방향 발판을 사용하며 벽차기를 요구하지 않는다. |
| F 숲 심부 | 왼쪽으로 가는 길에서 능력 습득 영역을 지난 뒤 낮게 드러난 연습 벽을 만난다. 바로 G로 들어가기 전에 가볍게 벽에 붙어 볼 수 있다. |
| G 암벽 연습로 | 1.5u 간격의 암벽 구간 3단, 중간 쉼턱 두 곳과 하단 안전 바닥을 둔다. 발판은 최저 바닥 위에 배치해 실패 후 다시 도전할 수 있게 했다. |
| H 상층 숲 | 완만한 능선과 선택 전투용 오소리를 둔다. 동쪽 끝 x29.5에서 아래의 B에 착지한다. |
| I 숲 출구 | B에서 보았던 암벽을 타고 올라가면 두 개의 작은 틈과 넓은 착지 구간을 지난다. 마지막 능선에서 기존 숲 탈출 진행 플래그를 기록한다. |

| 파일 | 위치와 동작 |
| --- | --- |
| `Assets/_Project/Scenes/ForestWhitebox.unity` | A, BC, C~I 각 루트의 `Editable Terrain Grid`에 일반 지형을 배치했다. `Terrain Source - Paint Here`에서 수정하고, `Preview Dual Grid`로 마스크를 확인할 수 있다. 경사는 기존 경사 타일을 사용한다. 게이트, 벤치, 스폰 지점, 단방향 발판은 각각의 역할을 가진 별도 씬 오브젝트다. `Forest Whitebox Camera > Rooms`와 `Forest Whitebox - Progression`의 영역·참조를 다시 맞췄다. |
| `Assets/_Project/Scripts/Runtime/World/ForestWhiteboxRoute.cs` | `exitClimbGate`를 추가했다. `Update()`에서 벽차기 진행 플래그가 없으면 B→I 뿌리 잠금을 유지하고, 습득 후 연다. H→B 도달은 능력 습득 후에만 기록한다. D·E의 기존 상호작용 방식과 체크포인트 ID는 유지한다. |
| `Docs/Reports/2026-11-06-forest-board-layout.png` | 새 파일. 씬 좌표의 실제 지형과 게이트를 표시한 단면도다. |
| `Docs/Reports/2026-11-06-forest-board-revision.md` | 새 파일. 변경 이유와 검증 범위를 기록한다. |

카메라 기본 배율과 플레이어 이동·점프 수치는 유지했다. 화면 경계와 지형이 방마다 달라지는지 확인할 수 있도록 기존 구역 카메라에 방을 추가했다. 소리 연출, 튜토리얼 문구, 최종 아트와 숲 탈출 연출은 이번 화이트박스에 포함하지 않았다. 일부 통로 길이와 카메라 범위는 Play 검증 후 조정할 값이다.

## Play 검증 순서

1. `ForestWhitebox`에서 새 진행 상태로 시작한다. 이전 저장에서 능력을 이미 얻었다면 I 게이트는 열린 상태로 시작하므로, 잠금 검증에는 별도의 임시 Editor 저장 파일명을 사용한다. 기존 저장을 지울 필요는 없다.
2. A에서 B로 진행해 I가 잠겼는지, BC에서 C로 내려갈 수 있는지, C의 잠긴 지름길을 보면서도 D로 갈 수 있는지 확인한다.
3. D에서는 멧돼지 처치 전과 후에 오른쪽 뿌리에 상호작용해 열리는 조건을 확인한다. 아래 E에 착지한 뒤 왼쪽으로 갈 수 있어야 한다. E에서 벤치와 C↔E 양방향 이동을 확인한다.
4. F에서 벽차기 습득, G의 하단 복구 및 두 쉼턱을 확인한다. H 오른쪽에서 B로 떨어진 뒤 I가 열렸는지 보고, I 마지막 능선에서 `ForestExitReached`가 기록되는지 확인한다.

저장된 타일·콜라이더 경계, 연결부와 갱도 폭, D의 최종 낙하 후 회차 공간, 씬 참조와 B 타일 데이터 보존을 정적으로 확인했다. Unity 6.4.7f1 프로젝트 참조를 사용한 런타임·편집기 C# 컴파일은 통과했다. Unity 배치 실행은 프로젝트 초기화에서 종료되어 씬 임포트와 A~I 연속 Play는 확인하지 못했다.
